# Проверка выгрузки ОСВ из 1С

Скрипт читает оборотно-сальдовую ведомость, сохранённую из 1С в XLSX или CSV, нормализует её и прогоняет бухгалтерские проверки: сходимость итогов, арифметику по каждому счёту и «красное сальдо». На выходе — разбор проблем человеческим языком и файл с найденными ошибками.

## Зачем

ОСВ выглядит как обычная таблица, но ломает стандартные инструменты: шапка в две-три строки с объединёнными ячейками, кодировка `windows-1251`, суммы с пробелами и запятой, строка «Итого» внутри данных. Из-за этого ошибки в выгрузке находят глазами, а не проверкой — и красное сальдо по кассе всплывает уже в отчётности.

## Быстрый старт

```bash
pip install -r requirements.txt
python src/check_osv.py data/raw/osv_2024_q3.xlsx
```

Пример вывода:

```
ОСВ: osv_2024_q3.xlsx
Период: 01.07.2024 - 30.09.2024
Счетов: 18

Итоги:
  сальдо на начало: Дт 3 306 000,00 / Кт 3 293 520,00 — расхождение 12 480,00 ₽
  обороты за период: Дт 10 577 000,60 / Кт 10 577 000,60 — ок
  сальдо на конец: Дт 3 788 000,00 / Кт 3 785 520,30 — расхождение 2 479,70 ₽

Проблем: 4
1. итоги по разделу «сальдо на начало» не сбалансированы: Дт больше Кт на 12 480,00 ₽...
2. по счёту 62 (Расчёты с покупателями и заказчиками) конечное сальдо не сходится с расчётом...
3. по счёту 50 (Касса) кредитовое сальдо 5 000,00 ₽ — «красное сальдо» на активном счёте...
```

Полный файл с расшифровкой каждой проблемы — `outputs/report.xlsx`.

## Проверки

1. **Сбалансированность итогов.** Сальдо на начало, обороты и сальдо на конец должны быть равны по дебету и кредиту. Расхождение обычно означает неполную выгрузку (фильтр по счёту или подразделению) либо нарушенную проводку в базе.
2. **Арифметика по каждому счёту.** Конечное сальдо = начальное + оборот Дт − оборот Кт. Разрыв — признак ручной правки файла или обрезанной выгрузки.
3. **Красное сальдо.** Кредитовый остаток на активном счёте (50, 51, 41, 10, 43…) и дебетовый на пассивном (80, 83, 96…). Активно-пассивные счета (60, 62, 68, 69, 71, 76, 84, 90, 91) не проверяются: развёрнутое сальдо для них нормально. Расхождения до 50 копеек считаются округлением и попадают в «Замечания», а не в «Проблемы».

## Что умеет читать

- XLSX с многострочной шапкой и объединёнными ячейками;
- CSV в `utf-8`, `utf-8` с BOM и `windows-1251`, с разделителем `;` или `,`;
- суммы вида `1 200 000,00`, `96 000,30`, `(500,00)` как −500, пустые ячейки и прочерки;
- счета с субсчетами (`62.01` приводится к `62`).

## Ключи

```bash
python src/check_osv.py osv.xlsx                        # человекочитаемый разбор
python src/check_osv.py osv.xlsx --json                 # то же в JSON
python src/check_osv.py osv.csv --csv outputs/osv.csv   # нормализованный CSV
python src/check_osv.py osv.xlsx --report outputs/osv.xlsx
```

## Структура

```
data/raw/             две выгрузки одной ОСВ: XLSX с merged-шапкой и CSV в cp1251
src/check_osv.py      парсинг, проверки, отчёт
outputs/report.xlsx   найденные проблемы и нормализованные данные
tests/                16 тестов
```

## Тесты

```bash
python -m unittest discover -s tests -v
```

Проверяются разбор сумм и колонок, поиск шапки, обе проверки, распознавание «Итого», устойчивость к cp1251 и совпадение результата для XLSX и CSV.

## Ограничения

- Скрипт читает **выгрузку**, а не базу 1С: отчёт нужно сохранить из 1С в XLSX или CSV.
- Из XLSX берётся первый лист, формулы читаются как сохранённые значения.
- Если структура не распознана, скрипт скажет об этом, а не выдаст молча пустой отчёт.
